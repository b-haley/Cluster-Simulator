# ClusterSim — симулятор кластерного планировщика

**ClusterSim** — дискретно-событийной симулятор планировщика вычислительного кластера с графическим интерфейсом на WPF. Проект воспроизводит ключевые механизмы распределения нагрузки промышленных систем (Sun HPC ClusterTools, Condor, MOL) и позволяет количественно сравнивать политики планирования: FIFO, Priority, EASY Backfill и Fair-Share.

Выполнен в рамках курсовой работы по теме *«Программное обеспечение для работы, балансировки нагрузки и объединения кластеров»*, но с максимальной проработкой каждой части: чистая архитектура, DI, миграции БД, тесты, dev-скрипты, воспроизводимые прогоны.

## Возможности

### Симуляция
- Кластер из неоднородных узлов (CPU, RAM, диск), включая полностью ручные конфигурации;
- Поток заданий: пуассоновское поступление, приоритеты, владельцы, требования к ресурсам, детерминированная генерация по seed;
- Параллельные задания на несколько узлов с планированием («все узлы или ничего») — аналог MPI-задач Sun HPC ClusterTools;
- Прерывание заданий с контрольными точками: сохранение остатка работы, накладные расходы, минимальное время до вытеснения — аналог checkpointing в Condor;
- Четыре политики планирования: **FIFO** (строгий / с пропуском головы), **Priority** (с вытеснением и без), **EASY Backfill** (резервирование под голову очереди + заполнение «окон»), **Fair-Share** (веса владельцев);
- Два режима прогона: **сравнение кластеров** и **совместные кластеры** (объединение узлов выбранных кластеров в единую систему);
- Автоматическое отклонение заданий, которые физически не помещаются в кластер; ограничение виртуального времени; трассировка событий.

### Аналитика
- Makespan, среднее ожидание, turnaround, slowdown, пропускная способность (заданий/час);
- Загрузка CPU и RAM — **интегральная** (площадь под кривой нагрузки), а не мгновенная;
- Загрузка **каждого узла и каждого кластера** в процентах, включая разбор совместного прогона;
- Временные ряды загрузки и длины очереди;
- Экспорт отчётов.

### Интерфейс (WPF)
- MVVM на source-генераторах, DI-контейнер;
- Возможность выбора темы: Neon и Light;
- Кластеры и профили заданий — карточками с ключевой информацией и всплывающими редакторами;
- Кастомные контролы: RangeSlider с двумя бегунками («от и до»), тумблеры, ScrollBar, DataGrid, вкладки;
- Вкладки с результатами заблокированы до первого прогона — интерфейс не показывает пустые состояния.

### Данные и инфраструктура
- PostgreSQL 17 в Docker: docker-compose с healthcheck и именованным томом;
- Схема БД создаётся и **мягко мигрирует** при старте приложения (`CREATE/ALTER … IF NOT EXISTS`) — старые базы подтягиваются без ручных скриптов;
- Хранилище конфигураций кластеров за интерфейсом `IClusterDefinitionStore`: реализации для PostgreSQL и файловой системы взаимозаменяемы;
- Dev-скрипты `start-dev.ps1` / `stop-dev.ps1` для подъёма и остановки окружения одной командой.

## Быстрый старт

### Требования

| Компонент | Версия |
|---|---|
| .NET SDK | 10.0+ |
| IDE | Visual Studio 2022/2026 (решение `ClusterSim.slnx`) или JetBrains Rider |

### Запуск в четыре команды

```bash
git clone <https://github.com/b-haley/Cluster-Simulator.git>
cd ClusterSim
docker compose up -d                 # поднять PostgreSQL
dotnet run --project src/ClusterSim.Wpf
```

Приложение само создаст схему БД при первом запуске. Параметры подключения берутся из `src/ClusterSim.Wpf/appsettings.Local.json` (образец — `appsettings.Local.example.json`); параметры контейнера — из `.env` (образец — `.env.example`).

> Без Docker приложение тоже запустится: инициализация БД пропустится, а хранилище конфигураций можно переключить на файловое заменой строки
```bash
services.AddClusterSimPostgres(LoadPostgresOptions());
```
на
```bash
services.AddSingleton<ClusterSim.Core.Features.Cluster.IClusterDefinitionStore>(_ =>
    new ClusterSim.Core.Features.Cluster.FileSystemClusterDefinitionStore(
        Path.Combine(Environment.GetFolderPath(Environment.SpecialFolder.MyDocuments), "ClusterSim", "cluster-store")));
```
в DI.
### Тесты


Тестовый набор проекта построен на **xUnit** и покрывает те слои, где сосредоточен основной риск логики: событийный движок, политики планирования, метрики и хранилища конфигураций. Каждый тест моделирует небольшой сценарий — несколько узлов и несколько заданий, — поведение которого можно предсказать, поэтому расхождение ожидания с реальностью всегда указывает на ошибку в алгоритме.

### Принципы построения тестов

- Движок в тестах получает задания от статического источника заданий (`IJobSource`), сценарии планирования полностью воспроизводимы от прогона к прогону;
- Ожидаемые времена старта, завершения и значения метрик выводятся вручную из условий сценария (например, «второе задание не может стартовать раньше, чем первое освободит узел»);
- Тесты файловых хранилищ работают во временных каталогах, которые удаляются после выполнения; тесты не зависят от состояния друг друга и от внешних файлов пользователя;
- Проверки PostgreSQL сами определяют доступность базы: если Docker-контейнер не поднят, они корректно пропускаются. Благодаря этому основной набор проходит на любой машине и в CI без дополнительной инфраструктуры, а при поднятой базе те же тесты превращаются в полноценную интеграционную проверку схемы и хранилища;
- Создание кластеров, заданий и контекстов планирования вынесено в общие помощники.

### Направления покрытия

- **Событийный движок.** Корректность порядка событий по виртуальному времени и при совпадении времён; жизненный цикл задания (поступление → запуск → завершение); освобождение ресурсов после завершения; отбраковка заданий, которые физически не помещаются в кластер; ограничение прогона по времени; прерывание с контрольной точкой и возобновление с сохранённым остатком работы.
- **Политики планирования.** Для каждой из четырёх политик проверяется её ключевое свойство: у FIFO — порядок очереди и блокировка головы в строгом режиме; у Priority — выбор по приоритету и корректность вытеснения; у EASY Backfill — заполнение «окон» простоя без задержки головы очереди; у Fair-Share — распределение ресурсов в пользу недообслуженного владельца с учётом весов. Политики проверяются как изолированно (на уровне формируемого плана), так и в полном прогоне через движок.
- **Генератор нагрузки.** Воспроизводимость потока заданий по seed, соблюдение заданных диапазонов ресурсов и длительностей, неубывание времён поступления, корректная генерация параллельных многоузловых заданий.
- **Метрики.** Корректность времени ожидания, оборота и замедления; интегральная загрузка ресурсов на сценариях с известной ответом нагрузкой (включая случай полного занятия кластера); учёт длины очереди; полнота временных рядов; раздельный учёт отклонённых и незавершённых заданий.
- **Хранилища конфигураций кластеров.** Файловая реализация: циклы «сохранить → загрузить», перезапись версии, удаление, список сохранённых конфигураций. PostgreSQL-реализация: подключение, создание схемы, сохранение и загрузка конфигурации вместе с узлами, удаление — с автоматическим пропуском при недоступной базе.

## Сценарий использования

1. **«Кластеры»** — создайте один или несколько кластеров: вручную в модальном редакторе (паспорт, шаблонная генерация узлов, ручная правка неоднородных узлов, выбор планировщика) или кнопкой «Создать стандартный экземпляр».
2. **«Задания»** — создайте профили нагрузки: количество заданий, seed, интенсивность, диапазоны длительности и ресурсов ползунками «от и до», доля параллельных заданий.
3. **«Запуск симуляции»** — отметьте профили заданий и кластеры, выберите режим: *сравнение кластеров* или *совместные кластеры*; при желании включите сравнение всех политик.
4. **«Результаты», «Задания прогона», «Сравнение политик»** — KPI-карточки, таблица загрузки по кластерам в процентах, временной ряд, детализация заданий и экспорт отчётов.

## Архитектура

| Проект | Ответственность |
|---|---|
| `ClusterSim.Core` | Доменные сущности (Job, ClusterNode, Cluster, ResourceVector), дискретно-событийный движок, политики планирования, сбор метрик, экспорт. Не зависит от UI, БД и логирования. |
| `ClusterSim.Infrastructure` | Доступ к PostgreSQL: фабрика подключений, идемпотентный инициализатор схемы, реализация `IClusterDefinitionStore`. |
| `ClusterSim.Wpf` | MVVM-интерфейс: ViewModel, модальные редакторы, дизайн-система и темы, фоновый запуск симуляции, снимки состояния для UI. |
| `ClusterSim.Tests` | ~40 тестов: очередь событий, движок, все четыре политики, метрики, детерминизм генератора, файловое хранилище, интеграция с PostgreSQL. |

### Организация Core: фичи и сквозная логика

```
ClusterSim.Core/
├─ Features/            # домен, сгруппированный по сущностям
│  ├─ Resources/        #   вектор ресурсов (CPU, RAM)
│  ├─ Job/              #   задание и его жизненный цикл
│  ├─ ClusterNode/      #   узел и сериализуемое определение узла
│  └─ Cluster/          #   кластер, фабрика, абстракция и файловое хранилище конфигураций
└─ Simulation/          # сквозная логика симуляции
   ├─ Engine/           #   виртуальное время, приоритетная очередь событий, движок
   ├─ Scheduling/       #   контракт политики, контекст, план, FirstFit, 4 политики
   ├─ Workload/         #   контракт IJobSource и детерминированный генератор
   ├─ Metrics/          #   интегральный сборщик загрузки и метрики прогона
   └─ Export/           #   CSV/JSON отчёты
```

## Политики планирования и их промышленные аналоги

| Политика | Механизм | Аналог в промышленных системах |
|---|---|---|
| FIFO | Строгий порядок очереди; опциональный пропуск головы | Базовый режим пакетных систем |
| Priority | Выше приоритет — раньше запуск; опциональное вытеснение | Приоритетное планирование Condor |
| Preemption + checkpoint | Остаток работы сохраняется, учитываются накладные расходы и минимальное время выполнения | Checkpointing в Condor |
| EASY Backfill | Резервирование ресурсов под голову очереди; короткие задания заполняют «окна», не задерживая голову | Backfill в Slurm / IBM LoadLeveler |
| Fair-Share | Ресурсы получает владелец с наименьшей нормированной долей с учётом весов | Fair-Share в Condor / Slurm |
| Gang scheduling | Параллельное задание занимает N узлов одновременно по принципу «все или ничего» | MPI-задания в Sun HPC ClusterTools |

## Технологический стек

- **Язык и платформа**: C# 14, .NET 10 (LTS), `net10.0-windows` для UI;
- **UI**: WPF, MVVM, CommunityToolkit.Mvvm (source-генераторы), собственная дизайн-система, темы и кастомные контролы;
- **Данные**: PostgreSQL 17, Npgsql (осознанный минимализм без ORM), System.Text.Json;
- **Инфраструктура**: Docker и docker-compose (healthcheck, volumes), PowerShell-скрипты разработчика;
- **Тесты**: xUnit, интеграционные тесты с автоматическим пропуском при недоступной БД;
- **Инструменты**: Visual Studio 2026 (формат решения `.slnx`), Git, GitHub.
